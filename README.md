# EtoA 게임판

배드민턴 모임 대진 관리 웹앱입니다. 별도 서버 없이 **GitHub Pages** 로 호스팅되는 정적 사이트입니다.

가로(랜드스케이프) 화면 기준으로 설계했습니다. 태블릿·노트북을 가로로 두고 쓰기에 가장 좋습니다.

---

## 화면 구성

```
┌──────────────────────────────────────────────────────────┐
│  EtoA 게임판        게임판 / 회원관리 / 계정관리 / 설정      │
├────────────────────────────────┬─────────────────────────┤
│  1번 코트   2번 코트            │  오늘의 참석자 선택       │
│  ┌──────┐  ┌──────┐            │  코트 3 · 대기 줄 3       │
│  │ ○  ○ │  │ ○  ○ │            │  자동 편성 / 랜덤 편성    │
│  │──네트─│  │──네트─│           ├─────────────────────────┤
│  │ ○  ○ │  │ ○  ○ │            │  대기 1 [4명]            │
│  └──────┘  └──────┘            │  대기 2 [4명]            │
│  3번 코트   4번 코트            │  대기 3 [ ]              │
│                                ├─────────────────────────┤
│                                │  미편성                  │
└────────────────────────────────┴─────────────────────────┘
```

- **코트** — 실제 배드민턴 코트(6.1m × 13.4m) 라인과 네트를 그대로 그렸고, 4명이 네트를 사이에 두고 2:2로 배치됩니다. 진한 초록은 경기 중, 연두는 빈 코트입니다.
- **대기** — 다음 순서로 들어갈 4명씩의 줄입니다.
- **미편성** — 아직 게임이 짜이지 않은 인원입니다. 경기가 끝난 사람은 이곳으로 돌아옵니다.

## 주요 기능

### 1. 인원 관리
- **회원**: DB에 계속 남습니다. `이름 · 급수 · 성별` 을 저장합니다.
- **게스트**: 당일만 유지되고 날짜가 바뀌면 자동으로 삭제됩니다.
- **오늘의 참석자 선택**: 게임판에서 버튼 한 번으로 오늘 나온 인원만 골라 담습니다. 선택한 사람만 미편성 목록에 나타납니다. 이 화면에서 게스트도 바로 추가할 수 있습니다.

### 2. 급수 점수표

|      | A   | B   | C   | D   | 초심 |
| ---- | --- | --- | --- | --- | ---- |
| 남   | 8.0 | 7.0 | 6.0 | 5.0 | 4.0  |
| 여   | 6.5 | 5.5 | 4.5 | 3.5 | 2.5  |

이 점수는 **편성 계산에만 쓰이고 화면에는 나오지 않습니다.** 코트·명단·기록 어디에도 표시되지 않으며, 관리자만 `설정 · 기록` 탭에서 필요할 때 켜서 확인할 수 있습니다(그 브라우저에만 적용). 운영진과 회원 화면에는 토글 자체가 없습니다.

### 3. 코트 운영
- 오늘 빌린 코트 수를 **1~4개** 중에서 지정합니다. 코트 수에 따라 배치가 달라집니다.
  - 1코트: 한 칸 / 2코트: 나란히 두 칸
  - 3코트: 위에 두 칸, 아래 한 칸을 가로로 넓게 (아래 칸은 네트가 세로인 가로형 코트)
  - 4코트: 2×2
- 코트마다 4명이 들어가고, 팀별 점수 합과 점수차가 코트 위에 표시됩니다.
- **경기 종료** 를 누르면 그 4명은 미편성으로 돌아가고, 개인 게임 수 · 4인 조합 · 파트너 조합이 기록됩니다.
- **자동 투입** 을 켜두면 경기 종료와 동시에 1번 대기가 그 코트로 들어가고 대기 줄이 한 칸씩 당겨집니다.

### 4. 대진 편성
- **드래그 앤 드롭**: 운영진이 인원 아이콘을 끌어 대기 줄이나 코트에 넣습니다. 미편성 → 대기, 대기 → 대기, 대기 → 미편성 모두 가능하고, 이미 사람이 있는 자리에 떨어뜨리면 서로 자리가 바뀝니다.
- **탭 이동**: 터치 화면에서는 인원을 한 번 누르고 목적지를 누르면 이동합니다.
- **⚡ 자동 편성**: 빈 코트 → 빈 대기 줄 순서로 채웁니다. (아래 규칙 A)
- **🎲 랜덤 편성**: **미편성 인원을 대기 줄로** 보냅니다. 코트는 건드리지 않습니다. (아래 규칙 B)
- **투입**: 대기 줄을 코트로 올립니다. 빈 코트가 여러 개면 어디로 보낼지 고르고, 하나뿐이면 바로 들어갑니다. 투입한 줄은 빠지고 뒤 대기 줄이 한 칸씩 앞으로 당겨집니다.
- **자동 투입**: 켜두면 경기 종료와 동시에 1번 대기가 그 코트로 들어갑니다.

### 5. 편성 규칙

#### 규칙 A — 자동 편성 (새로운 조합 우선)

| 순위 | 기준 |
| --- | --- |
| 0 | **[필수]** 양 팀 점수 합의 차이가 **1점 이내** 인 조합만 후보 |
| 1 | 그날 **해당 4인 조합** 이 함께 뛴 횟수가 적은 쪽 |
| 2 | 그날 **경기 수가 적은 사람** 이 포함된 쪽 |
| 3 | 그날 같은 **파트너** 로 짝을 이룬 횟수가 적은 쪽 |
| 4 | 위가 모두 같으면 그 안에서 **랜덤** |

> 예) `ABCD` 는 이미 한 게임을 했고 `ABCE` 는 아직 안 했을 때,
> `AB : CD` 가 동률이고 `AB : CE` 가 1점차라면 → **`ABCE` 를 우선 편성** 합니다.

1점 이내 조합이 하나도 없을 때만 허용치를 `1 → 1.5 → 2 → 3` 순으로 완화하며, 이 경우 안내 메시지가 뜹니다.

#### 규칙 B — 랜덤 편성 (게임 수 균등 우선)

| 순위 | 기준 |
| --- | --- |
| 1 | 4명의 그날 **게임 수 합** 이 적은 쪽. 단 가장 적은 합보다 **+2 까지는 같은 것으로** 봅니다 |
| 2 | 2:2 **점수차** 가 적은 쪽. **0.5점차까지는 0점차와 같은 것으로** 봅니다 |
| 3 | 그날 **해당 4인 조합** 이 함께 뛴 횟수가 적은 쪽 |
| 4 | 위가 모두 같으면 그 안에서 **랜덤** |

**성별 보정** — 양 팀의 성별 구성이 같으면(남복 · 여복 · 혼복) 점수차를 **0.5점 더** 봐줍니다. 즉 성별 구성이 맞으면 **1점차까지** 0점차와 동일하게 취급합니다.

> 예) `남A(8) · 여C(4.5)` vs `남D(5) · 여A(6.5)` 는 1점차지만 양쪽 다 혼복이라 0점차로 봅니다.
> 반면 `남A · 남D` vs `여A · 여C` 는 성별 구성이 달라 보정을 받지 못합니다.

#### 게임 중 인원 포함해서 편성

대기 줄을 짤 때 **지금 코트에서 뛰고 있는 사람** 도 후보에 넣는 토글입니다.

- 켜면 코트에서 뛰는 사람이 다음 대기 줄에 미리 들어갈 수 있습니다.
- 이때 그 사람의 게임 수는 **진행 중인 경기를 마친 것으로 보고 +1** 해서 계산하므로, 경기가 끝난 뒤에도 균등 배분이 맞습니다.
- 대기 줄에 있지만 아직 경기 중인 사람은 **주황색 표시** 가 붙고, 그 줄은 네 명이 모두 경기를 마칠 때까지 **투입할 수 없습니다.**
- 코트 편성에는 적용되지 않습니다. 한 사람이 두 코트에서 동시에 뛸 수는 없기 때문입니다.

### 6. 계정과 권한

| 권한 | 게임판 보기 | 대진 편성 | 회원 관리 | 계정 관리 |
| --- | :---: | :---: | :---: | :---: |
| 관리자 (admin) | O | O | O | O |
| 운영진 (staff) | O | O | O | - |
| 회원 (member) | O | - | - | - |
| 승인 대기 | - | - | - | - |

- **로그인하기 전에는 아무 화면도 보이지 않습니다.**
- 회원가입은 누구나 할 수 있지만, 관리자가 승인하기 전까지는 "승인 대기" 화면만 보입니다.
- 관리자는 가입 신청자에게 **회원** 또는 **운영진** 권한을 부여합니다.

**기본 계정** — 아이디 `admin` / 비밀번호 `1111`

> ⚠️ 공개 저장소로 배포되므로 **첫 로그인 후 반드시 비밀번호를 변경** 하세요.
> 상단의 `비밀번호` 버튼에서 바꿀 수 있습니다.

## GitHub Pages 배포

**최초 1회만** 저장소 소유자가 Pages 를 켜야 합니다. Pages 를 처음 활성화하는 권한은 소유자에게만 있고 워크플로 토큰으로는 할 수 없습니다.

1. 저장소 → **Settings → Pages**
2. **Build and deployment → Source** 를 **GitHub Actions** 로 변경
3. **Actions** 탭 → `Deploy to GitHub Pages` → **Run workflow** 로 한 번 실행 (또는 `main` 에 아무 커밋이나 푸시)

이후로는 `main` 에 푸시될 때마다 `.github/workflows/pages.yml` 이 자동으로 배포합니다.

배포 주소: `https://seyoungjo1.github.io/EtoA-game/`

## 데이터 저장 방식과 주의사항

이 앱은 서버가 없는 정적 사이트라 **모든 데이터가 브라우저의 localStorage 에 저장** 됩니다. 이 때문에 다음 제약이 있습니다.

- 회원 DB · 계정 · 오늘 기록은 **접속한 기기와 브라우저에만** 남습니다. 다른 사람의 휴대폰에서 접속하면 그 기기의 데이터가 따로 만들어집니다.
- 따라서 **운영진 한 대의 기기를 게임판 전용으로 정해서 쓰는 방식** 을 권장합니다. 나머지 인원은 각자 화면에서 보되, 실제 편성은 그 기기에서 합니다.
- 기기를 옮기거나 백업하려면 `설정 · 기록` 탭의 **JSON 내보내기 / 가져오기** 를 사용하세요.
- 브라우저 저장소를 지우면 데이터도 사라집니다. 주기적으로 내보내기를 권장합니다.
- 비밀번호는 SHA-256 으로 해시해 저장하지만, 클라이언트 전용이라 **강한 보안이 아닙니다.** 중요한 비밀번호를 재사용하지 마세요.

여러 기기에서 실시간으로 같은 데이터를 공유하려면 별도의 백엔드(Firebase, Supabase 등) 연동이 필요합니다.
